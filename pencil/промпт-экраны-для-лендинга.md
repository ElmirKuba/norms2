# Промпт: нарисовать экраны продукта для лендинга (шаг ·2)

> **Кому.** Мне же, работающему в VS Code с открытым `pencil/norms2.pen`. Скопировать целиком в
> новый чат вместе с фразой «работаем по этому промпту».
>
> **Зачем.** Шаг ·2 блока 2.9.2 требует **визуальный вход** для генерации лендинга: скриншоты живых
> экранов + экраны, нарисованные на холсте, с экспортом в картинки. Текстом композицию и характер
> движения не задать — попытка 1 (`landing-lab/1`) это доказала: сбылось пять признаков
> шаблонности из шести. Референс задаёт **форму**, содержание берём своё.

## Прежде чем что-либо делать

1. **Открыть `pencil/norms2.pen` вкладкой в VS Code.** MCP работает только с открытым документом;
   что не открыто — для меня не существует.
2. **Первый вызов — всегда:**
   `get_app_state({ include_schema: true, include_canvas_design: true, include_scripts_and_shaders: false, include_browser: false })`.
   Без схемы остальные инструменты использовать нельзя.
3. **`.pen` зашифрован.** `Read`, `Grep`, `cat` по нему — запрещены и бесполезны. Только инструменты
   Pencil.
4. **Не рисовать с двух сторон.** У Pencil свой встроенный агент (поле «Design anything…»).
   Либо он, либо я — одновременные правки затирают друг друга. Уточнить у Elmir, что поле не занято.

## Что уже на холсте

Один документ на весь проект, разделы разнесены по полотну и подписаны заметками. Порядок:
**компоненты сверху, секции ниже, растут вправо и вниз.** Существующие секции — «Айдентика»
(персонажи, аватарка канала) и «Превью релизов» (карточки 1200×630).

**Рисовать в стиле уже нарисованного,** а не заново: посмотреть существующие узлы и переиспользовать
компоненты и переменные документа.

## Железные правила холста

- **Цвета — только через переменные документа** (`accent`, `bg`, `text`, …). Они совпадают с
  [`_tokens.scss`](../angular/src/styles/_tokens.scss). Хардкод цвета — ошибка: правится переменная,
  меняются все макеты разом.
- **У новой секции обязательно `note` прямо на полотне**: что за секция, для какого шага плана, куда
  уходит результат, какие решения приняты и что отклонено — с датой и «почему». Заметка живёт вплотную
  к тому, что объясняет; README отвечает «как здесь всё устроено», заметка — «что это вот тут».
- **Отклонённое не удаляется молча.** Либо остаётся подписанным как отклонённое, либо удаляется, но с
  записью в заметке секции — иначе через месяц никто не вспомнит, что путь уже пробовали.
- **`out/` — только финальные версии.** Наброски живут на холсте.
- **Экспортированные картинки я не открываю.** Битое изображение в контексте валит последующие
  запросы. Рисую и экспортирую вслепую, правки вношу по словам Elmir — **приёмка глазами за ним**.
- **Редактор пишет на диск не сразу.** Перед коммитом Elmir жмёт `Ctrl+S`, иначе в git уедет старая
  версия. Мне — напомнить об этом явно.

## Задача

Завести секцию **«Экраны продукта — вход для лендинга»** и нарисовать в ней экраны, перечисленные
ниже. Источник содержания — [`база для лендоса полная.md`](../nest/seed-content/notifications/база%20для%20лендоса%20полная.md),
части I: там у каждого блока стоит пометка 🎨 с нужным экраном.

### Что рисовать, а что снимать скриншотом

Большинство экранов **уже существуют живьём** — их дешевле снять, чем рисовать. Рисовать имеет смысл
там, где нужен **идеализированный кадр**: без тестовых данных, с говорящим содержимым, в композиции,
годной для лендинга.

| # | Экран | Приоритет | Живьём есть? |
|---|---|---|---|
| 1 | **Дашборд «Акцента»: блок «Сейчас»** — одно дело, одна кнопка | 🔴 ключевой | да |
| 2 | **«Столкнулся»** — список готовых ответов в момент, когда накрыло | 🔴 ключевой | да |
| 3 | **Кольцо «Держусь»** со счётчиком и рекордом | 🟡 важный | да |
| 4 | **Карточка привычки с планкой** + строка «🎉 Планка выросла: 8 → 10» | 🟡 важный | да |
| 5 | **«Статистика»**: два числа постоянства + сетка достижений (неделя точками) | 🟡 важный | да |
| 6 | **Цель с графиком и вехами** + «ради чего откажусь» в зоне фокуса | 🟢 если останется время | да |
| 7 | **Таймер микро-победы** — полноэкранный спокойный отсчёт | 🟢 | да |
| 8 | **Страница-приглашение «Тебя пригласили!»** | 🟢 | да |

**Порядок работы:** сначала 🔴, показать Elmir, получить слова — и только потом 🟡. Не рисовать все
восемь вслепую: если тон не тот, восемь макетов переделывать дороже, чем два.

### Требования к содержимому кадров

- **Данные должны быть говорящими, а не «Lorem ipsum» и не тестовым мусором.** «1 отжимание»,
  «37 дней с действием», «5 из последних 7», «помогало 7 из 9» — числа из сценария, они уже осмысленны.
- **Никаких ПДн даже в макете.** Псевдонимы, а не имена: продукт [не хранит ПДн](../docs/152fz.md),
  и макет не должен намекать, будто хранит.
- **Показывать состояние «хорошо», но честно.** Не изображать наполненность: пустые блоки в продукте
  не рисуются вовсе — в макете тоже.
- **Тон — спокойный** ([ADR-0049](../docs/decisions/0049-accent-product-principles.md)): продукт про
  вычитание лишнего, а не про «успей больше». Никаких огненных градиентов и «взрывного роста».

## Куда уходит результат

Экспорт PNG в `pencil/out/` (это не потребляется кодом — человек берёт руками). Дальше картинки
идут как **визуальный вход** для ·2: вместе со скриншотами живых экранов они показываются модели
как референс формы при сборке лендинга (·5).

## Чего НЕ делать

- Не трогать секции «Айдентика» и «Превью релизов» — у них свои правила и свои потребители
  (превью ищет бэкенд по имени файла).
- Не менять переменные документа ради красоты одного макета: они общие с продуктом.
- Не решать за Elmir композицию лендинга. Здесь рисуются **экраны продукта** как исходный материал;
  сам лендинг — шаг ·5, и его форма определяется референсами, которые собирает Elmir.
