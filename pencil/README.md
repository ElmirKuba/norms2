# pencil/ — дизайн-исходники (Pencil)

> Здесь лежат исходники того, что рисуется, а не верстается: превью релизов для Telegram-канала,
> макеты экранов, схемы. Готовые артефакты (PNG) отсюда **экспортируются в другие папки** —
> в репозитории `pencil/` хранит источник, а не результат.

## Что за инструмент

[Pencil](https://pencil.dev) — редактор бесконечного холста, работает как расширение VS Code
и как отдельное приложение. Claude Code правит холст через MCP-сервер `pencil`.

**Файлы `.pen` зашифрованы.** Открывать их `Read`/`Grep`/`cat` бесполезно и запрещено: только
инструментами Pencil. В git они едут бинарём — `git diff` по ним не читается, история хранит
факт изменения, а не построчную правку.

⚠️ **У Pencil есть свой встроенный агент** — поле «Design anything…» внизу окна. Не дёргать холст
с двух сторон: либо рисует он, либо Claude Code через MCP. Одновременные правки затирают друг друга.

⚠️ **Редактор пишет на диск не сразу.** Пока файл не сохранён (`Ctrl+S`), изменения живут в памяти
редактора, и в git уедет старая версия. Перед коммитом — сохранить.

## Почему один файл, а не файл на каждую тему

`norms2.pen` — **один документ на весь проект**, разделы разнесены по холсту и подписаны
заметками (`note`). Так решено 04.08.2026, причины:

1. **Компоненты не переходят между файлами.** Reusable-компонент (например, шаблон карточки
   релиза) переиспользуется только внутри своего документа; в соседний его можно лишь скопировать —
   и с этого момента копии живут отдельно и разъезжаются.
2. **Переменные тоже принадлежат документу.** Токены (`accent`, `bg`, `text`, …) заданы один раз
   и совпадают с [`_tokens.scss`](../angular/src/styles/_tokens.scss). Раздели файл — токены
   продублируются, а дубли рано или поздно разойдутся. Та же болезнь, от которой мы лечимся
   везде в проекте.
3. **Чтобы опираться на уже нарисованное, оно должно быть под рукой.** MCP работает с
   **открытым** документом; всё, что в другом файле, для ассистента невидимо, пока файл не открыт
   вкладкой. Один холст = вся история решений доступна сразу, новое рисуется в стиле старого,
   а не заново.

**Когда всё-таки делить:** если файл станет тяжёлым для редактора. Тогда резать по-крупному
(например, «превью» отдельно от «экранов»), сознательно приняв, что токены придётся держать
синхронно руками.

## Как устроен холст

Порядок: **компоненты сверху, секции ниже, растут вправо и вниз**. У каждой секции — заметка
(`note`) над её содержимым: что это, для какого шага плана, куда уходит результат.

| Секция | Что там | Куда идёт результат |
|---|---|---|
| **Превью релизов** | карточки 1200×630 к каждой релиз-ноте | PNG → [`nest/seed-content/notifications/previews/`](../nest/seed-content/notifications/previews/) |

## Превью релизов — правила

- **Размер ровно 1200×630**, экспорт PNG с масштабом **1** (не 2: Telegram ужимает, а вес поста
  растёт втрое).
- **Имя файла — по ключу ноты**: `release-2.9.0.png` рядом с `release-2.9.0.md`. По этому имени
  адаптер находит картинку, отдельного реестра нет.
- **Цвета — только через переменные документа.** Значения повторяют тёмную тему продукта;
  градиент фона — акцент, подмешанный в фон (35% и 22%), то есть то же, что дал бы `color-mix`.
  Правится переменная — меняются все карточки разом.
- **Приёмка глазами — за Elmir.** Claude Code картинки не открывает: битое изображение в контексте
  валит последующие запросы. Он рисует и экспортирует вслепую, правки вносит по словам.

Зачем это всё и как превью попадает в канал — [ADR-0064](../docs/decisions/0064-telegram-release-channel.md),
шаги ·4.6 и ·4.7 в [`docs/impl-phase2-plan.md`](../docs/impl-phase2-plan.md).
