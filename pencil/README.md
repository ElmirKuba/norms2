# pencil/ — дизайн-исходники (Pencil)

> Здесь лежат исходники того, что рисуется, а не верстается: превью релизов для Telegram-канала,
> макеты экранов, схемы.

## Раскладка

```
pencil/
  norms2.pen   ← холст (источник, зашифрован)
  out/         ← экспортированные бинарники: PNG/JPEG/WEBP/PDF
  README.md
```

**`out/` — только финальные версии** (реш. Elmir 04.08.2026). Промежуточные прогоны и наброски
туда не кладём: это не свалка экспортов, а «то, что готово к употреблению». Черновик живёт на
холсте; в `out/` он попадает, когда принят.

**Исключение — артефакты, которые читает код.** Превью релизов бэкенд ищет рядом с нотами, в
[`nest/seed-content/notifications/previews/`](../nest/seed-content/notifications/previews/), и
экспортируются они сразу туда: держать один и тот же PNG в двух местах — значит завести две версии,
которые однажды разойдутся. В `out/` уходит то, что никакой код не потребляет и что человек берёт
руками, — аватарка канала, баннеры, картинки для постов.

## Что за инструмент

[Pencil](https://pencil.dev) — редактор бесконечного холста, работает как расширение VS Code
и как отдельное приложение. Claude Code правит холст через MCP-сервер `pencil`.

**Файлы `.pen` зашифрованы.** Открывать их `Read`/`Grep`/`cat` бесполезно и запрещено: только
инструментами Pencil. В git они едут бинарём — `git diff` по ним не читается, история хранит
факт изменения, а не построчную правку.

⚠️ **У Pencil есть свой встроенный агент** — поле «Design anything…» внизу окна. Не дёргать холст
с двух сторон: либо рисует он, либо Claude Code через MCP. Одновременные правки затирают друг друга.

⚠️ **Редактор пишет на диск не сразу.** Пока файл не сохранён (`Ctrl+S`), изменения живут в памяти
редактора, и в git уедет старая версия. Перед коммитом — сохранить.

## Почему один файл, а не файл на каждую тему

`norms2.pen` — **один документ на весь проект**, разделы разнесены по холсту и подписаны
заметками (`note`). Так решено 04.08.2026, причины:

1. **Компоненты не переходят между файлами.** Reusable-компонент (например, шаблон карточки
   релиза) переиспользуется только внутри своего документа; в соседний его можно лишь скопировать —
   и с этого момента копии живут отдельно и разъезжаются.
2. **Переменные тоже принадлежат документу.** Токены (`accent`, `bg`, `text`, …) заданы один раз
   и совпадают с [`_tokens.scss`](../angular/src/styles/_tokens.scss). Раздели файл — токены
   продублируются, а дубли рано или поздно разойдутся. Та же болезнь, от которой мы лечимся
   везде в проекте.
3. **Чтобы опираться на уже нарисованное, оно должно быть под рукой.** MCP работает с
   **открытым** документом; всё, что в другом файле, для ассистента невидимо, пока файл не открыт
   вкладкой. Один холст = вся история решений доступна сразу, новое рисуется в стиле старого,
   а не заново.

**Когда всё-таки делить:** если файл станет тяжёлым для редактора. Тогда резать по-крупному
(например, «превью» отдельно от «экранов»), сознательно приняв, что токены придётся держать
синхронно руками.

## Как устроен холст

Порядок: **компоненты сверху, секции ниже, растут вправо и вниз**.

| Секция | Что там | Куда идёт результат |
|---|---|---|
| **Айдентика** | персонажи, аватарка канала | PNG по месту; порядок — персонажи первыми |
| **Превью релизов** | карточки 1200×630 к каждой релиз-ноте | PNG → [`nest/seed-content/notifications/previews/`](../nest/seed-content/notifications/previews/) |
| **Экраны продукта — вход для лендинга** | экраны «Акцента» по фактической вёрстке | **HTML** → `out/screens/`, оттуда разметка вклеивается в лендинг |

### Экраны продукта: HTML, а не PNG (реш. Elmir 07.08.2026)

Экраны для лендинга экспортируются **разметкой**, а не картинкой: тогда цвета можно свести к
`var(--color-*)` из [`_tokens.scss`](../angular/src/styles/_tokens.scss), и экран **сам
переключается вместе с темой страницы**. PNG так не умеет: снимок тёмной темы останется тёмным
на светлом лендинге. Образец — `~/coding/landing-lab/4/`, где экспорт вклеен прямо в
`index.html` (отдельным файлом он не подгружается, это исходник для вставки).

🪤 **Экспорт сам переменных НЕ сохраняет** (проверено 07.08.2026 на всех пяти экранах): хотя на
холсте цвета заданы переменными документа, в HTML уезжают развёрнутые `#14151A`, `#E8915B`. Файл
в полигоне 4 выглядит «правильным» только потому, что его правили руками. **После каждого
экспорта — прогнать замену**, иначе экран останется намертво тёмным:

```bash
cd pencil/out/screens && sed -i -E \
  -e 's/#14151[aA]/var(--color-bg)/g' \
  -e 's/#1[dD]1[fF]27/var(--color-surface)/g' \
  -e 's/#262932/var(--color-surface-2)/g' \
  -e 's/#313542/var(--color-border)/g' \
  -e 's/#[eE]7[eE]9[eE][eE]/var(--color-text)/g' \
  -e 's/#9[aA][aA]0[aA][dD]/var(--color-text-muted)/g' \
  -e 's/#[eE]8915[bB]/var(--color-accent)/g' \
  -e 's/#1[aA]1206/var(--color-on-accent)/g' \
  -e 's/#4[bB][bB][fF]7[bB]/var(--color-success)/g' \
  -e 's/#5[eE]4031/color-mix(in srgb, var(--color-accent) 30%, var(--color-bg))/g' \
  -e 's/#433028/color-mix(in srgb, var(--color-accent) 16%, var(--color-bg))/g' \
  -e 's/box-shadow: 0px 2px 8px 0px #0000004D/box-shadow: var(--shadow-1)/g' \
  *.html
grep -oE '#[0-9a-fA-F]{3,8}' *.html   # должно быть пусто
```

Две нижние строки — про `accent-deep` и `accent-mid`: этих переменных в продукте **нет**, они
живут только в документе Pencil, поэтому разворачиваются в `color-mix` от акцента — то же, что
уже делает CSS раздела. Проверка `grep` обязательна: пустой вывод = ни одного цвета, застрявшего
в одной теме.

**Рисуем по факту вёрстки, а не «как красивее».** Размеры, отступы, радиусы и цвета берутся из
scss самого компонента; идеализируются только **данные** — числа из сценария, псевдонимы вместо
имён, пустые блоки не рисуются вовсе (в продукте их тоже нет). Повод для правила: «Привычки ·
Шаблоны» был по смыслу верным, а вживую выглядел иначе — такой макет врёт о продукте.

Ограничения инструмента, которые **нельзя принимать за дизайн** (подробнее — в заметке секции на
холсте): пунктирной обводки в Pencil нет, `color-mix` с прозрачностью не воспроизводится
(градиенты сделаны затуханием в поверхность), backdrop модалки не рисуется — цвета для него в
токенах нет.

### Правило: у каждой секции — заметка на холсте (обязательно)

Над содержимым каждой секции стоит узел `note` — **подпись прямо на полотне**, а не в этом файле:
что это за секция, для какого шага плана, куда уходит результат, какие решения уже приняты и что
из этого отклонено (с датой и «почему»).

**Зачем именно на холсте, если есть README:** дизайн смотрят глазами, а не читая доку рядом.
Заметка живёт вплотную к тому, что объясняет, — и её видит и человек, открывший файл через полгода,
и ассистент, который читает документ целиком одним вызовом. README отвечает на вопрос «как здесь
всё устроено», заметка — на вопрос «что это вот тут и почему так».

Правило заведено 04.08.2026 по решению Elmir. Отклонённые подходы **не удаляются молча**: либо
остаются на холсте подписанными как отклонённые, либо удаляются, но с записью об этом в заметке
секции — иначе через месяц никто не вспомнит, что этот путь уже пробовали.

## Превью релизов — правила

- **Размер ровно 1200×630**, экспорт PNG с масштабом **1** (не 2: Telegram ужимает, а вес поста
  растёт втрое).
- **Имя файла — по ключу ноты**: `release-2.9.0.png` рядом с `release-2.9.0.md`. По этому имени
  адаптер находит картинку, отдельного реестра нет.
- **Цвета — только через переменные документа.** Значения повторяют тёмную тему продукта;
  градиент фона — акцент, подмешанный в фон (35% и 22%), то есть то же, что дал бы `color-mix`.
  Правится переменная — меняются все карточки разом.
- **Приёмка глазами — за Elmir.** Claude Code картинки не открывает: битое изображение в контексте
  валит последующие запросы. Он рисует и экспортирует вслепую, правки вносит по словам.

Зачем это всё и как превью попадает в канал — [ADR-0064](../docs/decisions/0064-telegram-release-channel.md),
шаги ·4.6 и ·4.7 в [`docs/impl-phase2-plan.md`](../docs/impl-phase2-plan.md).
